# Sutura — REST API Contract (Phase 1 Discovery)

Base path: `/api/v1`. OpenAPI docs auto-generated by FastAPI at `/api/v1/openapi.json` /
`/api/v1/docs`. This document fixes the surface and conventions Phase 3+ builds against; it is not a
full OpenAPI schema (field-by-field types are in `erd.md`).

## 0. Conventions (apply to every endpoint below)

**Auth.** Every endpoint except `auth/*` requires a valid access token
(`Authorization: Bearer <jwt>` for both web and mobile). The access token itself never travels in a
cookie (CSRF defense, D-026) — only in the `Authorization` header. The refresh token travels
exclusively as an httpOnly, `SameSite=Lax`, path-scoped (`/api/v1/auth`) cookie set by
`/auth/login` and rotated by `/auth/refresh` (D-026); it is never present in any JSON request or
response body. **Known gap:** this is currently cookie-only, which works for the browser-based web
client but not yet for the Flutter mobile client (a cookie jar isn't the natural token store on
mobile) — the Mobile phase (spec §47) needs an explicit decision here (e.g. a `platform` hint that
switches `/auth/refresh` to also accept a body-delivered token for non-browser clients) before
mobile auth is implemented; don't assume the current cookie-only shape silently extends to mobile.
Every query is filtered by the authenticated user's `id` at the repository layer — never by
trusting an `id` in the path alone.

**Ownership / cross-user access.** Requesting a record ID that exists but belongs to another user
returns `404 Not Found`, identical to a genuinely missing ID (D-020) — never `403`.

**Pagination.** List endpoints accept `page` (default 1) and `page_size` (default 25, max 100).
Response shape:
```json
{
  "data": [ ... ],
  "meta": { "page": 1, "page_size": 25, "total_items": 137, "total_pages": 6 }
}
```

**Filtering.** Resource-specific filters are query params (documented per resource below). Two
universal filters apply wherever relevant: `financial_period_id` and `date_from`/`date_to`
(inclusive, `YYYY-MM-DD`).

**Sorting.** `sort_by=<field>&sort_dir=asc|desc`. Default sort is `-created_at` (newest first)
unless noted.

**Error envelope.**
```json
{
  "error": {
    "code": "VALIDATION_ERROR",
    "message": "Distribution category percentages must sum to exactly 100%.",
    "field_errors": [
      { "field": "categories[2].percentage", "message": "..." }
    ]
  }
}
```
Standard codes used: `400` malformed request, `401` unauthenticated, `404` not found / not yours,
`409` conflict (e.g. editing a closed period, stale `updated_at`, percentage-sum violation,
over-allocation), `422` schema validation failure, `500` unexpected.

**Money in requests/responses.** All monetary fields are JSON strings (e.g. `"amount": "1500.0000"`),
never JSON numbers — this avoids clients silently round-tripping money through floating-point JSON
parsers. Percentages are strings too (e.g. `"percentage": "30.00"`).

**Never-trust-the-client rule (§46).** No endpoint in this API accepts a `total_*` or other derived
field as authoritative input. Totals, remainders, and summaries are always response-only fields
computed server-side from persisted records.

**Optimistic concurrency (D-018).** `PATCH`/`DELETE` on money-affecting resources require an
`If-Unmodified-Since` header (or an `updated_at` field in the body — chosen: header, to keep body
schemas write-only) echoing the value last read; mismatch returns `409`.

## 1. Auth (`/api/v1/auth`)

| Method | Path | Notes |
|---|---|---|
| POST | `/auth/register` | email, password, full_name → creates user, sends verification email |
| POST | `/auth/login` | email, password → `{access_token}` in the body; refresh token is set as an httpOnly `Set-Cookie` (D-026), never returned in JSON |
| POST | `/auth/refresh` | no body; refresh token is read from the cookie. Rotates it — revokes the presented token and sets a **new** refresh cookie alongside the new `{access_token}`. Missing/invalid/revoked/expired cookie → `401` |
| POST | `/auth/logout` | no body; reads the refresh token from the cookie, revokes it server-side, and clears the cookie |
| POST | `/auth/verify-email` | token from email link |
| POST | `/auth/resend-verification` | |
| POST | `/auth/forgot-password` | email → sends reset link |
| POST | `/auth/reset-password` | token, new_password |
| POST | `/auth/mfa/enable` | returns TOTP secret/QR |
| POST | `/auth/mfa/verify` | code → activates MFA |
| GET | `/auth/oauth/{provider}/redirect` | OIDC redirect |
| GET | `/auth/oauth/{provider}/callback` | OIDC callback → tokens |

## 3. Financial Periods (`/api/v1/financial-periods`)

| Method | Path | Notes |
|---|---|---|
| GET | `/financial-periods` | filters: `year`, `status`; paginated, sorted by `-year,-month` default |

| GET | `/financial-periods/{id}/summary` | live-computed if `OPEN`; latest `MonthlyFinancialSummary` (`is_current`) if `CLOSED` |
